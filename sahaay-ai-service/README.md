# SAHAAY – AI & Smart Features Service

Standalone **Python + FastAPI** microservice implementing the AI and
Smart Features module of the SAHAAY Food Wastage Prediction and
Redistribution Platform. It is designed to run independently of the
main Flutter app + backend/database, and to be called over HTTP.

## What this service does

| # | Feature | Endpoint |
|---|---------|----------|
| 1 | AI-based food surplus prediction + preparation recommendation | `POST /api/v1/prediction/predict-surplus` |
| 2 | Weighted-scoring NGO matching (with real road-distance/GPS routing) | `POST /api/v1/matching/rank-ngos` |
| 3 | Auto-escalation to next NGO | `POST /api/v1/escalation/check` |
| 4 | Restaurant reliability scoring | `POST /api/v1/reliability/calculate` |
| 5 | Rule-based food safety verification | `POST /api/v1/safety/verify` |
| 6 | PDF donation acknowledgment | `POST /api/v1/donation/generate-acknowledgment` + `GET /api/v1/donation/download/{donation_id}` |

Full interactive documentation (Swagger UI) is auto-generated by
FastAPI at `/docs` once the server is running.

## 1. Project structure

```
sahaay-ai-service/
├── app/
│   ├── main.py                  # FastAPI app, includes all routers
│   ├── config.py                # All tunable constants & weights
│   ├── models/
│   │   └── schemas.py           # All Pydantic request/response models
│   ├── core/                    # Business logic (no FastAPI code here)
│   │   ├── prediction.py        # Loads model, runs surplus prediction
│   │   ├── matching.py          # NGO scoring + ranking
│   │   ├── escalation.py        # Auto-escalation rule
│   │   ├── reliability.py       # Restaurant reliability score
│   │   ├── safety.py            # Food safety rule engine
│   │   └── pdf_generator.py     # ReportLab PDF generation
│   ├── routers/                 # FastAPI route definitions (thin layer)
│   │   ├── prediction_router.py
│   │   ├── matching_router.py
│   │   ├── escalation_router.py
│   │   ├── reliability_router.py
│   │   ├── safety_router.py
│   │   └── donation_router.py
│   ├── ml/
│   │   ├── train_model.py       # Trains & saves the surplus model
│   │   ├── surplus_model.pkl    # Generated after training (not in git)
│   │   └── encoders.pkl         # Generated after training (not in git)
│   ├── data/
│   │   └── sample_surplus_data.csv   # Sample training data
│   └── storage/                 # Generated acknowledgment PDFs (not in git)
├── tests/
│   └── test_api.py              # Pytest API tests
├── requirements.txt
├── .gitignore
├── README.md                    (this file)
└── INTEGRATION.md               # For the main backend team
```

**Design note:** `core/` holds all the actual logic as plain Python
functions with no FastAPI dependency. `routers/` is a thin HTTP layer
that just validates input (via Pydantic) and calls into `core/`. This
separation makes the logic independently testable and easy to reuse
(e.g. from a batch script) without spinning up the API.

## 2. Setup instructions

### Prerequisites
- Python 3.10+ installed
- pip

### Step-by-step

```bash
# 1. Move into the project folder
cd sahaay-ai-service

# 2. Create and activate a virtual environment (recommended)
python -m venv venv
# Windows:
venv\Scripts\activate
# macOS/Linux:
source venv/bin/activate

# 3. Install dependencies
pip install -r requirements.txt

# 4. Train the surplus prediction model (creates .pkl files)
python -m app.ml.train_model

# 5. Run the API server
uvicorn app.main:app --reload --port 8000
```

The service will be live at: `http://127.0.0.1:8000`
Interactive Swagger docs: `http://127.0.0.1:8000/docs`

> Note: If you skip step 4, the service will still work — the first
> API call to `/predict-surplus` will automatically train the model
> using the sample dataset before responding.

## 5. GPS / Road-distance routing (NGO matching)

The matching engine (`app/core/matching.py`) supports two ways of
calculating distance between a restaurant and a candidate NGO:

- **Road distance ("road")** — calls a routing API (OSRM, free, no API
  key needed for development) and returns real driving distance in km.
  This is what actually gets used by default.
- **Straight-line distance ("straight_line")** — the haversine
  (great-circle) formula, used automatically as a **fallback** if the
  routing API call fails for any reason (no internet, API down,
  request timeout).

This means the matching endpoint never crashes due to a network issue
— it just silently falls back to straight-line distance and keeps
working. Every response tells you which method was actually used, via
the `distance_source` field on each NGO in the response:

```json
{
  "ngo_id": "NGO001",
  "distance_km": 3.2,
  "distance_source": "road",
  ...
}
```

**Settings** (in `app/config.py`):
- `USE_ROAD_DISTANCE` — set to `False` to always use straight-line
  distance only (useful for offline development/testing).
- `OSRM_BASE_URL` — points at the free public OSRM demo server by
  default. For production, replace this with your own hosted OSRM
  instance, or swap `get_road_distance_km()` in `matching.py` for a
  call to a paid provider like Google's Distance Matrix API.
- `ROAD_DISTANCE_TIMEOUT_SECONDS` — how long to wait for the routing
  API before giving up and falling back (default: 3 seconds).

**Where the coordinates come from:** this service does not store or
manage location data — the main backend/database is responsible for
capturing restaurant and NGO latitude/longitude (e.g. from a map
picker in the Flutter app) and passing them in the request body to
`/api/v1/matching/rank-ngos`.

## 6. Running with Docker (optional)

If you'd rather not set up Python locally, or want to deploy this as
a container, a `Dockerfile` is included.

```bash
# Build the image (also trains the model during build)
docker build -t sahaay-ai-service .

# Run the container
docker run -p 8000:8000 sahaay-ai-service
```

Then open `http://127.0.0.1:8000/docs` same as before. The model is
trained automatically during the image build, so the container is
ready to serve requests as soon as it starts.

To retrain with a real dataset later, replace
`app/data/sample_surplus_data.csv` and rebuild the image
(`docker build -t sahaay-ai-service .` again).

---

## 7. Retraining the model with real data

Once the restaurant/NGO team has real historical data, replace
`app/data/sample_surplus_data.csv` with a real dataset that has these
columns:

```
food_prepared_kg, food_sold_kg, food_category, day_of_week, date, surplus_kg
```

Then re-run:
```bash
python -m app.ml.train_model
```

This overwrites `surplus_model.pkl` and `encoders.pkl` with a model
trained on the new data. No other code changes needed.

## 8. Notes on the PDF acknowledgment

The generated PDF is explicitly labeled as an **impact/acknowledgment
receipt only** and carries a disclaimer that it is **not** a Section
80G tax-deduction certificate. Do not remove this disclaimer without
checking with a legal/accounting advisor for the project.
